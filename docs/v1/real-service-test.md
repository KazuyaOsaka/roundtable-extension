# 実サービスでの接続試験：本人にお願いする操作

各社へのログイン、コネクタの登録、トンネルの公開は、本人のアカウントとPCでしか行えません。以下の順に進めてください。所要時間の目安は、準備30分、各社の単独試験15〜20分ずつ、連結試験30分です。

**記録の原則**
- AIの自己申告ではなく、**各社の画面で見えたこと**を議長画面の「接続試験」タブの記録欄に書いてください。
- 確認ダイアログが出たら、**何の操作で何回出たか**を書いてください。承認した場合も「承認した」と書きます。
- 試験の開始後は、AIの画面に**文字を入力・送信しない**でください。入力した場合は、その旨を記録してください。

---

## 0. このPCで Roundtable を起動する

1. ターミナルで `node -v` を実行し、`v22` 以上であることを確認します。違う場合は https://nodejs.org/ から LTS を入れてください（Homebrew なら `brew install node`）。
2. 今の作業フォルダ（`~/Documents/roundtable-extension`）には触れず、**別のフォルダ**に取得します。未コミットの変更を守るためです。
   ```
   git clone -b ccr-85719f93-q7j8p2 https://github.com/KazuyaOsaka/roundtable-extension.git ~/Documents/roundtable-v1
   cd ~/Documents/roundtable-v1/app
   npm ci
   npm start
   ```
3. 表示された議長画面 http://127.0.0.1:8787/ をブラウザで開きます。

## 1. トンネルで参加者用ポートを公開する（本人の同意が必要）

**公開されるもの**：参加者用ポート 8788 だけです（`/mcp/<秘密のトークン>`・`/p/<秘密のトークン>`・`/healthz`）。トークンを知らない人がアクセスしても「見つかりません」になります。議長画面は公開されません。
**リスク**：MCP URL・参加者ページの URL を知った人は、その参加者として会議を読み、投稿できます。URL は他人に渡さないでください。漏れたら「接続設定」→「URLを作り直す」を押してください。使わないときはトンネルを止めてください。

最初の試験は、アカウント不要の Cloudflare クイックトンネルが手軽です。

1. `brew install cloudflared`
2. 別のターミナルで `cloudflared tunnel --url http://127.0.0.1:8788` を実行し、表示される `https://….trycloudflare.com` をコピーします。
3. 議長画面の「接続設定」→「公開URL」に貼り付けて「保存」を押します。
4. ブラウザで `https://….trycloudflare.com/healthz` を開き、`ok` と出ることを確認します。

注意
- クイックトンネルは、起動のたびに URL が変わります。そのたびに各社のコネクタの URL を登録し直す必要があります。繰り返し使う場合は、Cloudflare の名前付きトンネル（独自ドメインが必要）か、ngrok の固定ドメインを使ってください。
- クイックトンネルは SSE に対応していません。Roundtable は通常の JSON で応答するので、影響はありません。同時接続の上限は200件、稼働の保証はありません。
- ngrok の無料版では、ブラウザでのアクセス時に警告ページが挟まります。Gemini の参加者ページ方式では、cloudflared を推奨します。

## 2. 会議を作る

議長画面の「会議」タブで、議題に「接続試験」などの短い試験用の文を入れて作成します。私的な内容は使わないでください。記録を公開する場合があります。

## 3. Claude の単独試験

**登録（初回のみ）**
1. claude.ai → Customize（設定）→ Connectors → ＋ →「Add custom connector」
2. 名前を `Roundtable`、URL を議長画面「接続設定」の **Claude の MCP URL** にして追加します（認証なし）。
3. コネクタの設定で、`post_message`・`report_problem`・`panel_claim_wake`・`panel_report_wake` を「Always allow」にします。できなかった場合や安全確認が出た場合は、記録してください。

**試験1：タスク内待機**
1. 「接続試験」タブで、対象＝Claude、受け取り方＝「タスク内で待機」、待機＝「すぐ」を選びます。表示された指示をコピーします。
2. claude.ai で新しいチャットを開き、＋ → コネクタで Roundtable を有効にして、指示を貼って送信します。
3. 議長画面の「会議」タブで、Claude が「待機中」になったことを確認します。
4. 「試験開始」を押します。以後、Claude の画面には触れません。
5. 結果表の「判定」と「Bの受け取り方」を確認します。
6. 待機を「3分」に変えて、同じ手順を繰り返します（チャットは新しく作ってください）。

**試験2：パネルによる再起動**
1. 受け取り方＝「終了後に再起動：パネル（MCP App）」の指示をコピーし、新しいチャットに貼って送信します。
2. パネルが表示され、Claude の応答が終わったことを確認します。
3. 「試験開始」を押します（すぐ／3分）。**Claude のタブは開いたまま、前面に表示しておいてください**（背面ではブラウザがタイマーを遅らせます）。
4. パネルに「通知 … sent」と出たか、Claude が自分で次の発言を始めたかを確認します。確認ダイアログやクリックの要求が出た場合は記録してください。

記録欄には、画面上のモデル名、Project の利用有無、Memory のオン・オフを書いてください。

## 4. ChatGPT の単独試験

**登録（初回のみ）**
1. chatgpt.com/plugins → ＋ →「Add custom MCP server」
2. Server URL を **ChatGPT の MCP URL**、認証を「No authentication」にして作成し、自分のプラグインとしてインストールします。
3. プラグインのページに、ツール（get_my_turn など）とイベント（turn.assigned）が表示されることを確認します。表示されない場合や、書込みツールが使えないと出た場合は、プランと一緒に記録してください。資料上、Plus/Pro で書込みツールが使えるかは未確認です。
4. アプリの確認設定を「重要な変更の前だけ」にします。

**試験1：MCP Events（本命）**
1. 「接続試験」タブで、対象＝ChatGPT、受け取り方＝「終了後に再起動：MCP Events」の指示をコピーします。
2. ChatGPT の **Work チャット**（Web 版。デスクトップ版なら Work＋Cloud）を開き、`@Roundtable` を付けて指示を送信します。
3. 議長画面の「接続設定」タブの下にある購読一覧に、ChatGPT の購読が表示されることを確認します。
4. 「試験開始」を押します（すぐ／3分）。以後、ChatGPT の画面には触れません。
5. 確認ダイアログが出たら、何回出たかを記録します（承認した場合も記録）。

**試験2（任意）：タスク内待機**
受け取り方＝「タスク内で待機」の指示で、同じように試します。

## 5. Gemini の単独試験

1. Gemini で **Tasks**（タスクモード）を開きます。Google AI Pro/Ultra、個人アカウント、Personal Intelligence への参加が必要です。
2. 「接続試験」タブで、対象＝Gemini、受け取り方＝「参加者ページ（ブラウザ）」の指示をコピーし、タスクとして開始します。
3. Gemini が参加者ページを開き、「STATUS: WAITING」を読んだことを確認してから、「試験開始」を押します（すぐ／3分）。
4. フォーム送信の確認が出たら、**回数と、承認したかどうか**を記録します。公式資料上、この確認は省略できない可能性があります。
5. 依頼B（3分後）を Gemini が自分で読み込み直して投稿したか、タスクが先に終わったかを記録します。

米国の個人アカウントで Custom apps（MCP）が使える場合は、MCP URL を登録して「タスク内で待機」も試せます。公式資料上、書込みは毎回確認が必要です。

## 6. 三社の連結試験（2巡・6発言 → 3巡・9発言）

1. 「接続設定」タブで、各社の「次の番の起こし方」を、単独試験で成立した方式にします。
   - 例：Claude＝タスク内待機＋パネル、ChatGPT＝MCP Events、Gemini＝参加者ページ
2. 各社に新しいチャット（またはタスク）を用意し、「接続設定」タブの「開始時の指示」を送ります。全員が待機中、購読済み、またはページを開いた状態にします。
3. 「接続試験」タブ →「2巡・6発言で開始」。以後、AIの画面には触れません。確認ダイアログが出た場合は承認し、回数を記録します。
4. 結果表で「人の操作なしで届いた回答 6」「直前のAIを引用 5」を確認します。最後に、2巡目の発言が前の参加者の内容を具体的に踏まえているかを、**人が読んで判断**してください。
5. 成立したら「3巡・9発言で開始」を試します。
6. **途中停止の試験（別試験）**：もう一度「2巡・6発言で開始」を押し、どれかのAIが「処理中」のときに「停止」を押します。新しい依頼が出ないこと、遅れて届いた回答が「旧前提・未転送」と表示されることを確認します。

## 7. 四者会談の基本操作

「会議」タブで次を試します。
- 議長として発言 →「全員に聞く」
- 「Claude に聞く」などの指名
- 自動進行中に「発言のみ／割込」→ 一時停止 → 再開

## 8. 結果を残す

- 「接続試験」タブ →「結果をJSONで保存」、「記録・出力」タブ → Markdown／JSON
- [verification.md](verification.md) の表に結果を書き写すか、保存したファイルを Codex のレビューに渡してください。公開する場合は、URL のトークン部分を伏せてください。

## うまくいかないときの記録の仕方

| 起きたこと | 記録すること | 次に試すこと |
|---|---|---|
| Claude のパネル通知に、クリックや確認が必要だった | 「パネル再起動：クリック必要」 | タスク内待機を主に使う |
| Claude が途中で「Continue」を求めて止まった | そのときの発言数・待機回数 | パネル再起動との併用 |
| ChatGPT で Work やイベントが使えない／書込みツールが使えない | プランと画面の表示 | タスク内待機（使える場合） |
| ChatGPT が投稿のたびに確認を求めた | 回数と設定内容 | 確認設定の変更 |
| Gemini が送信のたびに確認を求めた | 回数 | （公式仕様のため回避しません） |
| Gemini のタスクが1回投稿して終わった | 終了までの動き | タスクの再開が本人操作になることを記録 |
| 「確認待ち？」のまま進まない | AI側の画面の状態 | AI側で承認 → だめなら「再通知を許可」または「スキップ」 |
