# Roundtable

議長（人間）と Claude・ChatGPT・Gemini による四者会談、そして議長が役割を指定した三者の自動討論を行う会議室です。

- 各AIは、**それぞれの公式機能**で会議室を読み、自分の発言を投稿します。使う機能は、Claude のカスタムコネクタ／MCP App、ChatGPT のカスタムMCP／MCP Events、Gemini の Tasks（ブラウザ）です。
- 各社の推論API、APIキー、従量課金の推論サービスは使いません。Claude Code・Codex などの開発CLIを参加者に置き換えることもしません。
- 会議の進行と議事録は、このPCで動く Roundtable サーバーが一か所で管理します。

## 起動

Node.js 22 以上が必要です。

```
cd app
npm ci
npm start
```

- 議長画面：http://127.0.0.1:8787/（このPCからのみ開けます）
- 参加者用ポート：http://127.0.0.1:8788/（トンネルで公開します）
- データ保存先：`app/data/`（議事録・接続用トークン・購読情報。コミットしないでください）

環境変数（任意）

| 変数 | 既定 | 内容 |
|---|---|---|
| `RT_CHAIR_PORT` | 8787 | 議長画面のポート |
| `RT_PARTICIPANT_PORT` | 8788 | 参加者用ポート |
| `RT_DATA_DIR` | `app/data` | 保存先 |
| `RT_PUBLIC_URL` | （画面で設定） | 公開URL（トンネルの https URL） |
| `RT_WAIT_MAX_SEC` | 50 | `wait_for_my_turn` の1回の最大待機秒数。ChatGPT のツール時間上限（約60秒・非公式）と、トンネルの上限を考えて決めています |

## 初回設定（概要）

詳しい手順は [docs/v1/real-service-test.md](docs/v1/real-service-test.md) にあります。

1. **トンネル**：`cloudflared tunnel --url http://127.0.0.1:8788` などで参加者用ポートを公開し、https の URL を議長画面「接続設定」に保存します。公開されるのは参加者用ポートだけです。
2. **Claude**：claude.ai の Connectors で、カスタムコネクタに「Claude の MCP URL」を登録します（認証なし）。
3. **ChatGPT**：chatgpt.com/plugins で、カスタムMCPサーバーとして「ChatGPT の MCP URL」を登録します（No authentication）。**Work チャット**で使います。
4. **Gemini**：Tasks に「参加者ページ」の指示を渡します（米国の個人アカウントなら Custom apps の MCP も使えます）。
5. 会議を作り、「接続設定」の**開始時の指示**を各AIに一度だけ送ります。以後の転記は不要です。

## 使い方

- **四者会談**：議長として発言し、「全員に聞く」または「◯◯に聞く」を押します。「独立回答」にすると、互いの回答を見ずに答えます。
- **AIだけで続ける**：進め方（自由討論／理論構築）、回数上限、時間上限を決めて「開始」を押します。発言順と役割は「会議設定」で決めます。
  - 理論構築プリセット：独立案（並行・相互非公開）→ 相互批判 → 改訂 → 検証方法の整理
  - 役割プリセット：発散／反論・検証／統合（自由記述も可）
- **割込**：自動進行中に「発言のみ／割込」を押すと、一時停止します。処理中だった回答は「旧前提」として記録され、他のAIには渡りません。「再開」で続きます。
- **一時停止／再開／停止／会議を終了**：右側のパネルから操作します。
- **参加者の状態**：待機・依頼済み・処理中・投稿済み・確認待ち？・エラー・未接続が表示されます。
- **記録**：発言は原文のまま保存され、要約は別欄に付けます。「記録・出力」から Markdown・JSON で保存できます。仮説には、既存理論との違い・固有の予測・反証条件・必要な観測を記録できます。再読み込みやサーバーの再起動をしても、状態は復元されます。

## 既知の制限と未確認事項

- **実サービスでの動作は未確認**です（上記 B・C）。特に次の点は、実機試験の結果しだいです。
  - claude.ai のパネルが、クリックなしで次の発言を起こせるか
  - Claude が1ターンでツールを何回呼べるか（非公式な報告では約20回）
  - ChatGPT の Plus/Pro で書込みツールと MCP Events が使えるか
  - Gemini Tasks がページの再確認を続けられるか
- **Gemini は、投稿のたびに本人の確認が入る見込み**です。Google の公式資料に、書込み・フォーム送信の前に確認すると明記されています。Roundtable はこの確認を回避しません。
- パネル（MCP App）による通知は、AIのチャット画面がブラウザで開いている間だけ働きます。背面のタブでは遅れます。
- クイックトンネルは、起動のたびに URL が変わります。そのたびに各社への登録をやり直す必要があります。
- 一度に開ける会議は1つです。PC とサーバーが動いている間だけ使えます。音声・課金・多人数・複数会議の同時進行には対応していません。
- 参加者の認証は、URL に含まれる秘密のトークンで行います（OAuth は未対応）。URL を他人に渡さないでください。
- AIが同じ依頼を2回生成することは防げません。会議側の受理・記録・進行が1回だけになることを保証しています。

### 旧 Chrome 拡張について

旧版は、各社の Web 画面を DOM 操作で動かす Chrome 拡張でした（Phase 3 まで実装、Phase 4 は `feature/phase4-turn-control` ブランチ）。v1 では使いません。理由は次の3つです。

- 各社の利用規約にある自動アクセスの禁止に抵触するおそれがある
- bot 検知を入力の揺らぎで回避していた
- 毎回の「了解」返答と全履歴の再投入を前提としていた

コードは削除せずに残しています（[docs/v1/architecture.md](docs/v1/architecture.md) の「旧コードの扱い」）。
